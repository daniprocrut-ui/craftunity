# Craftunity Launcher

Лаунчер Minecraft для сервера **craftunity.mcsh.io** и отдельная лёгкая админ-панель.
Клиент — `Craftunity_launcher.exe`, панель — `Admin.exe` (нативное окно, без браузера и WebView).
Загрузчик всегда **Fabric**, версия клиента одна для всех.

## Что уже работает

| Возможность | Реализация |
|---|---|
| Запуск Minecraft | официальные файлы Mojang, Fabric-загрузчик (всегда) |
| Одна версия у всех | подписанный манифест, Ed25519-подпись, лаунчер принимает только свой манифест |
| Админ-панель | отдельный `Admin.exe`: сборка, модпак, клиенты, раздача манифеста |
| Моды из лаунчера | каталог Modrinth, установка в `game/mods`, модпак из манифеста ставится сам |
| Скины | предпросмотр, локальное применение, загрузка на ely.by |
| Аккаунты | оффлайн-ник и вход через ely.by (authlib-injector) |
| Автовход на сервер | `--quickPlayMultiplayer craftunity.mcsh.io:25565` |
| Heartbeat | клиент сообщает админке свою версию и ник |
| Автообновление | новый exe берётся из подписанного манифеста, проверяется по sha256 и подменяется при следующем запуске |
| Сайт загрузки | статическая страница `site/index.html` для GitHub Pages, файлы — в GitHub Releases |

## Быстрый старт

```powershell
dist\Craftunity_launcher.exe      # лаунчер
dist\Admin.exe         # админ-панель (открывается окно, без браузера)
```

Из исходников:

```powershell
python -m pip install -r requirements.txt
python run.py            # лаунчер
python admin_run.py      # админ-панель
python tests\smoke.py    # проверка API
python tests\updater_check.py  # проверка логики обновления
```

## Админ-панель

Четыре вкладки:

* **Сборка** — версия сборки, версия Minecraft, версия Fabric (пусто = последняя стабильная),
  адрес и порт сервера, JVM-аргументы, сообщение игрокам. Кнопка «Сохранить и опубликовать»
  пересобирает манифест и подписывает его.
* **Модпак** — список модов по `project_id`/`slug` из Modrinth, которые лаунчер поставит автоматически.
* **Клиенты** — кто запускал игру, с какой версией и когда последний раз (heartbeat).
* **Публикация** — встроенный раздатчик манифеста: адрес, порт, кнопки «Запустить/Остановить сервер»,
  URL для настроек лаунчера, путь к ключам подписи.

Пароля у панели нет: это локальное настольное приложение, наружу оно ничего не отдаёт,
кроме самого манифеста (если включить раздачу).

Панель не нужна игрокам и не нужна для раздачи: манифест лежит на GitHub Pages, поэтому
клиенты забирают его сами, даже когда ваш компьютер выключен. Вкладка «Публикация» осталась
для локальной сети и отладки, а релизы выходят через `python tools\release.py`.

## Как работает «одна версия у всех»

1. Админ задаёт параметры сборки и публикует манифест.
2. Манифест подписывается приватным ключом `%APPDATA%\Craftunity\admin\manifest_private.pem`.
3. Публикуются два файла: `manifest.json` и `manifest.json.sig` (папка `%APPDATA%\Craftunity\admin\publish`),
   а `tools\release.py` кладёт их в `site/` и вместе с exe отправляет на GitHub.
4. Лаунчер скачивает их с GitHub Pages, проверяет подпись встроенным публичным ключом
   (`keys\craftunity_manifest_pub.pem`) и только потом ставит клиент и модпак.

Адрес манифеста зашит в сборку: `DEFAULT_MANIFEST_URL` в `craftunity/config.py` переписывается
скриптом релиза на `https://<user>.github.io/<repo>/manifest.json`, поэтому игроку ничего
настраивать не нужно — запустил exe и он сам подтянул актуальную версию.

Подменить манифест по пути нельзя: без приватного ключа подпись не совпадёт, лаунчер остановит запуск.
Админка **не отправляет команды** на машины игроков — только публикует манифест, который клиент
сам забирает при запуске. Никаких удалённых команд, скриптов и загрузки кода.

## Автообновление лаунчера

Версия лаунчера лежит в том же подписанном манифесте, поэтому подменить обновление нельзя:

```json
"launcher": {
  "version": "1.1.0",
  "url": "https://…/Craftunity_launcher.exe",
  "sha256": "…",
  "notes": "что нового",
  "mandatory": false
}
```

1. При запуске и далее каждые 5 минут лаунчер в фоне сверяет `launcher.version` с собственной версией.
2. Если версия новее — скачивает exe в `%APPDATA%\Craftunity\update` и сверяет `sha256`.
3. Подмена происходит при следующем запуске: текущий exe переименовывается в `.old`, новый встаёт
   на его место, лаунчер перезапускается с флагом `--updated`, а `.old` удаляется при следующем старте.
4. Во время игры ничего не происходит: окно не перезапускается и загрузка не мешает.

`mandatory: true` или `min_launcher` новее установленной версии — единственный случай, когда старая
версия не запускается: обновление ставится сразу, как только игра закрыта. Если хостинг недоступен,
лаунчер работает на кэшированном манифесте и не блокируется.

Манифест берётся не с вашей машины, а со статического хостинга, поэтому обновления уходят игрокам
без включённой админки. Если GitHub Pages не ответил, лаунчер пробует зеркала из
`MANIFEST_FALLBACKS` (jsDelivr и raw.githubusercontent), затем кэш — порядок именно такой.

### Где взять URL манифеста

* Локально/в одной сети: включите сервер на вкладке «Публикация», скопируйте URL вида
  `http://192.168.1.10:8765/launcher/manifest.json` и вставьте его в настройках лаунчера.
* Для интернета: манифест и exe публикуются на GitHub Pages + GitHub Releases
  (`python tools\release.py <версия>`), лаунчер получает адрес вида
  `https://<user>.github.io/<repo>/manifest.json`.

`craftunity.mcsh.io` — адрес игрового сервера, а не веб-сервер: по 80/443 он не отвечает,
поэтому статику (сайт, exe, манифест) там разместить нельзя, нужен отдельный HTTPS-хостинг.

Публичный ключ из `%APPDATA%\Craftunity\admin\craftunity_manifest_pub.pem` должен совпадать
с `keys\craftunity_manifest_pub.pem` в сборке лаунчера, которая раздаётся игрокам.
Если ключ пересоздан — пересоберите лаунчер с новым публичным ключом.

## Моды

* Поиск и установка из Modrinth, фильтр по версии игры и Fabric.
* Обязательные зависимости мода ставятся автоматически.
* Модпак из манифеста синхронизируется при каждом запуске.

## Аккаунты

* **Оффлайн** — ник 3–16 символов, UUID считается по `OfflinePlayer:<ник>`.
* **ely.by** — логин и пароль уходят напрямую на `authserver.ely.by`, пароль не сохраняется,
  остаётся только токен. Для игры подключается `authlib-injector`
  (`https://authserver.ely.by/api/authlib-injector`), поэтому работают скины и авторизация ely.by.

## Скин

PNG 64×64 (или 64×32), модель classic/slim. Локальный скин виден в лаунчере;
на сервере он отображается при входе через ely.by или с серверным плагином скинов.

## Требования

* Windows 10/11, WebView2 Runtime для лаунчера (в системе по умолчанию).
* Java 17+ для Minecraft 1.18+, Java 21 для 1.20.5+. Путь можно задать в настройках.
* Интернет для первой установки клиента (~350 МБ ресурсов).

## Сборка exe

```powershell
# лаунчер
python -m PyInstaller --noconfirm --onefile --windowed --name Craftunity_launcher `
  --icon icon.ico --add-data "ui;ui" --add-data "keys;keys" `
  --hidden-import webview --hidden-import clr `
  --collect-all webview --collect-submodules pythonnet run.py

# админ-панель (лёгкая, без webview)
python -m PyInstaller --noconfirm --onefile --windowed --name Admin `
  --icon icon.ico --add-data "icon.ico;." --add-data "ui/styles.css;ui" `
  --exclude-module webview --exclude-module clr --exclude-module pythonnet admin_run.py
```

Админка берёт оформление из темы лаунчера: при запуске читает `theme` из
`%APPDATA%\Craftunity\settings.json` и применяет ту же палитру (все 14 тем).
Сменили тему в лаунчере — при следующем запуске панель откроется в ней же.

Результаты: `dist\Craftunity_launcher.exe` (~18 МБ) и `dist\Admin.exe` (~16 МБ).

## Публикация релиза и сайта

```powershell
python tools\release.py 1.1.0 --notes "Что нового" --repo <user>/<repo> [--mandatory] [--push]
```

Скрипт прописывает в `craftunity/config.py` адрес манифеста на GitHub Pages, зеркала
(`MANIFEST_FALLBACKS`) и `GITHUB_REPO`, поднимает `LAUNCHER_VERSION`, собирает `Craftunity_launcher.spec`,
считает sha256, заливает exe в GitHub Releases (`gh release create`), вписывает блок `launcher`
в манифест, подписывает его, копирует `manifest.json` и `.sig` в `site/`, обновляет ссылку на
релизы в `site/index.html` и коммитит изменения. `--dry-run` показывает план без изменений,
`--no-upload` и `--skip-build` — для отладки, `--no-commit` — если коммит нужен вручную.

Первая настройка хостинга:

1. Создать репозиторий на GitHub и подключить его как `origin` (`gh auth login` для загрузки релизов).
2. Settings → Pages → Source: ветка `main`, папка `/site`.
3. Прописать в лаунчере (или в `craftunity.json`) адрес `https://<user>.github.io/<repo>/manifest.json`.
4. `keys\craftunity_manifest_pub.pem` в сборке должен совпадать с публичным ключом
   из `%APPDATA%\Craftunity\admin\`, иначе клиенты отклонят манифест.

Страница `site/index.html` читает `./manifest.json` рядом с собой и подставляет версию,
дату, «что нового» и ссылку на скачивание. Если манифеста нет, страница остаётся рабочей
и ведёт на страницу релизов.


## Передача другим игрокам

Лаунчер самодостаточен: Python, интерфейс, ключ подписи и CA-бандл внутри exe. Достаточно передать
один файл Craftunity_launcher.exe (18 МБ). При первом запуске:

* клиент, ресурсы и Fabric скачиваются с официальных серверов Mojang/Fabric;
* если Java 17/21 не найдена, лаунчер сам скачает Temurin JRE в %APPDATA%\Craftunity\runtime;
* настройки и аккаунт создаются в %APPDATA%\Craftunity у каждого игрока отдельно.

Чтобы у всех была одна версия и сервер, положите рядом с exe файл craftunity.json:

`json
{
  "manifest_url": "https://<user>.github.io/<repo>/manifest.json",
  "server_host": "craftunity.mcsh.io",
  "server_port": 25565,
  "memory_mb": 4096
}
`

Файл применяется один раз при первом запуске (дальше игрок может менять настройки в лаунчере).
Без craftunity.json лаунчер работает на значениях по умолчанию и локальном кеше манифеста.

Требования у получателя: Windows 10/11 x64 и интернет. SmartScreen может предупредить,
что издатель неизвестен — это ожидаемо для неподписанного exe (подпись требует сертификата кода).

## Ограничения и честные оговорки

* **ely.by не проверен в этой среде**: TLS-сертификат `authserver.ely.by` не проходил проверку
  (`certificate has expired`), поэтому вход и загрузку скина протестировать не удалось.
  Код использует официальные эндпоинты authlib-injector, но это нужно проверить на вашей машине.
* Автообновление опирается на подписанный манифест: файл берётся только по ссылке из манифеста
  и проверяется по sha256, поэтому произвольный exe клиент не примет. Но если приватный ключ
  `%APPDATA%\Craftunity\admin\manifest_private.pem` утечёт, злоумышленник сможет подписать свой
  манифест — ключ нужно хранить только на машине админа. Сам exe не подписан сертификатом кода,
  поэтому SmartScreen предупреждает о неизвестном издателе.
* Манифест по умолчанию указывает на `https://craftunity.mcsh.io/launcher/manifest.json` — этот
  адрес не отвечает (там только игровой сервер), поэтому после публикации на GitHub Pages
  поменяйте `DEFAULT_MANIFEST_URL` в `craftunity/config.py` или пропишите адрес в `craftunity.json`.
* CurseForge не подключён (нужен API-ключ), моды только из Modrinth.
* Файлы игры скачиваются с официальных серверов Mojang; пиратские сборки не распространяются.
